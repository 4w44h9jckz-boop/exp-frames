lambdaclass/ethrex `c94964843d39d04914dff178e55e60daf7707089` (branch `hegota-testnet`), rustc 1.97.0,

```bash
EXP27_CASES=$EXP/erc-assets/cases.txt \
  cargo test -q --release -p ethrex-blockchain --features ethrex-crypto/default \
    --test exp27_execution_digest -- --nocapture
```

## Under EIP-8250 at master (`1a086d5c`), with `ethrex/eip8250-master.patch`

The patch changes four rules and nothing else:
- static validation admits up to 16 keys, `[]` included, and drops "key 0 only alone";
- `[]` checks and consumes the sender's legacy nonce, and charges new-account state gas when the
  sender does not exist;
- every key, key 0 included, is a `NONCE_MANAGER` sequence;
- a transaction is keyed when its key list is not empty.

Without the patch, every case that uses `[]` is refused in the static checks, "Invalid frame
transaction format: nonce_keys count must be between 1 and 16". That is ten wrong verdicts and
eight right ones for the wrong reason, which test nothing of the account. Only the two keyed
cases, `keyed-nonces` and `key-zero`, reached the account, and both were accepted.
