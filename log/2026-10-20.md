### Done

- **F4, one registry for two applications** (this repository `88ad0be`, kohaku-rs `3e95bfc`).
  Experiment 32's `OwnedStateRegistry` is its own sender and holds the notes of every
  application in one MiMC tree. A note is $H(\mathrm{tag}, \mathrm{inner}, \mathrm{state})$ and
  its nullifier $H(\mathrm{tag}, \mathrm{nullifierSecret})$. A kernel proof (`kernel.circom`,
  33,287 constraints) is checked in `VERIFY`, with the nullifier as the nonce key and the root
  through EIP-8272. Two applications, `FixedPool` (experiment 06's pool as a rule) and
  `Balance` (any amount, partial spends with a change note), and a control, `StoredRule`.
  Run once on the testnet (`npx tsx experiments/32-owned-state/run.ts`):
  - **Both applications write to one registry, and both self-updates were mined.** The same
    secrets, deposited in both, gave two nullifiers: A (`0x511572f1`, block 479,289, FixedPool)
    and B (`0xa5b18e15`, block 479,291, Balance with a 0.002 ETH change note). C (`0x587e541e`,
    block 479,292) spent the change note.
  - **A nullifier from one application is refused by the other.** A's proof with Balance's tag
    was refused before A (D1); the prover cannot make a Balance update with FixedPool's
    nullifier (D2); after A, its nullifier is refused whichever application claims it (D4).
  - **The check needs no storage outside the sender.** The registry's `VERIFY` reads no
    storage. The control, whose rule reads one slot of its own contract, was refused at
    admission with `StorageReadNonSender` (E3).
  - `VERIFY` costs 229,302 to 229,326 gas per update, over EIP-8141's 100,000 and under the
    testnet's 500,000, and 15,494 less than experiment 06's keyed pool.
  - kohaku-rs's new `crates/frame-registry` (`kohaku-frame-registry`) rebuilds the three updates
    byte for byte from the fixtures, verifies their proofs with its own Groth16 check, recomputes
    the deposits' leaves and the tree's roots with `kohaku-tornadocash`'s MiMC (now exported as
    `mimc_sponge`), and matches `registry.ts`'s kernel input for a spend signal by signal.

### Learned

- **A shared tree is not a shared crowd.** The tag is public, so an update's anonymity set is
  its application's notes. The registry shares a root publication, a verifier and a nonce-key
  space, not privacy; hiding the tag needs the application's rule inside the proof.
- **What an application may check in `VERIFY` is code only.** State it keeps in its own
  contract has to move into the note, the proof or the registry's storage.
- **A change note costs a deposit**: 977,066 gas through experiment 06's hasher contract.
- The phase-2 setup has one contribution, made here with discarded entropy; the proving key is
  committed so the deployed verifier stays usable (README, "The proving key"). Phase 1 is the
  PSE perpetual powers of tau; Hermez's file returned 403.

Phase 3 opened (`enews` decision 0099, read at `c7e01da`). F7 first.

### Done

- **Where the blind-issuance layer lives: kohaku-rs, with Commonware unchanged.** The new crate
  `kohaku-frame-ticket` (kohaku-rs `2770696`, `b6a63b1`) depends on `commonware-cryptography`

  and `Scalar::inv` are all it takes, with multiplicative blinding `B = r * H(m)`. The issuers'
  key comes from one round of `dkg::feldman_desmedt` among them.
- **Experiment 36** (this repository `f0749cb`), run by kohaku-rs's

    noble's BLS12-381 to rebuild every spend byte for byte, check every ticket and every

- **Would show it wrong: not observed.** Nothing the issuers or the chain hold matched an answer

- **The issuers must share one count.** Counted per issuer, 4 issuers with a quorum of 3 issue 4

## The wallet session, phase 3: F9, a private read paid with a ticket

### Done

- **Read upstream's `kohaku-privacy-rpc`** (ethereum/kohaku-rs, branch `experiments/pir-v1`, at
  `6dc83a4`), which `enews` had not read. It composes `kohaku-pir-rpc`, a router that answers
  `eth_getBalance`, `eth_getTransactionCount` and `eth_getCode` from an account backend, with Tor.
  The account value is 40 bytes: delegate, a 12-byte balance, an 8-byte nonce. Its PIR lookup over
  Tor (`TorPirLookup`) posts the keys themselves to the server. Its comment says the body codec is
  to be replaced with a PIR client's, so on that branch the server learns what is read, though not
  from whom.
- **kohaku-rs `cbb77e6`, a new crate `kohaku-ticket-read`.** It has five parts:
  - single-server PIR in the style of SimplePIR, with its parameters;
  - the account table in hashed buckets;
  - a read ticket, issued by the same committee and key as F7's gas tickets, under its own
    namespace;
  - a read server that checks the ticket and its own spent set before any work;
  - `TicketLookup`, a `LookupBackend` for upstream's `kohaku-pir-rpc`, taken as a git dependency
    at `6dc83a4`.

  `tests/read.rs` runs the whole path offline.
- **Experiment 37** (this repository `34a744e`), run by `examples/ticket_read.rs` at `cbb77e6`.
  A shop (experiment 36's paymaster, for this committee's key) sold 4 tickets in block 480,956.
  The table holds the 40 code-free accounts active in blocks 477,957 to 480,957, as of 480,957.
  Three private reads through the router each spent one ticket and matched the node. The server
  refused a spent ticket, a ticket for another server and a forged one, each before any work. Its
  log holds no address. `rebuild.test.ts` checks every read ticket with noble, for its own server
  and for no other.

### Learned

- **Would show it wrong: not observed at these sizes.** A read's server work was 4 to 9
  microseconds on the testnet's 7,200-byte table, and 21.1 ms on a 64 MiB table (3.18 GB/s on
  one core). Checking the ticket took about 1 ms. No market prices either. A ticket is 0.001
  testnet ETH, which a gas spend used a third of in experiment 36.
- On the testnet's table the ticket check is most of the server's work: the scan passes it at
  about 3.2 MB of table. And PIR's hint (1.97 MB) is larger than the table, so downloading the
  table would have been cheaper and as private.
- Read and gas tickets can share one crowd: the issuers cannot tell which namespace a blinded
  point will carry.
