# 2026-11-11

## The phase 4 wallet session: an absent address in a checked-read table

### Done

- **The defect, reproduced offline before any fix.**
  - Experiment 39's table rule admits every address seen in a transaction whose code is empty,
    so a table can hold an address with no code, no balance and no nonce.
  - Under EIP-161 such an address is not in the state trie, and `eth_getProof` returns a proof of
    absence.
  - kohaku-rs `crates/checked-read` at `74d2b3d`:
    - its reader refused the honest record: "the branch proves the account absent";
    - its judge, given the refusal's evidence and the same proof, returned `Wrong { chain: None }`
      against the honest server. The test framing an honest server was meant to exclude that, but
      here it came through the table rather than the query.
- **The fix**, kohaku-rs `experiment/checked-read-absent` at `317bd59`.
  - An account a branch proves absent reads as the empty account (`AccountState::EMPTY`: no
    nonce, no balance, no storage, no code). That is what `eth_getBalance` answers for it.
  - The reader accepts a record claiming exactly that, and the judge finds it correct. A record
    claiming more for an absent address is still refused, and found wrong.
  - The new test `an_absent_address_in_the_table_reads_as_empty_and_frames_no_one`, on the random
    trie, failed before the fix in both places and passes after.
  - All of the crate's tests pass, and clippy is clean.
  - The table rule is unchanged. "No record means unanswered" is unchanged too.

### What it changes for experiment 39

Nothing in its accepted run. That run read its target, an account that exists, and an address the
table does not hold, which is unanswered with or without the fix. The fix only changes reads of an
address the table holds and the state lacks.
