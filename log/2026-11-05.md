## The phase 4 wallet session: Q8, TFHE's input proof ported to leanVM

### Done

- **Pre-registered before any code:** experiment 41's post-quantum run (`1c53e5f`). It is a port:
  it measures the model, not tfhe-rs's own proof.
- **Version 1** (32-bit halves under $g$) proved and verified at $d = 64$ to $1024$. At
  $d = 2048$ leanVM refused it: the committed witness would be $2^{30}$ words, past its $2^{28}$
  bound (amendment 1, `15dd54f`).
- **Version 2** (one exponent of a primitive $h$ of $\mathrm{GF}(2^{192})^\times$, bytes through
  tables, a 16 by 16 tiled product) proves $d = 2048$:
  - $k = 1$: 5,974,185 cycles, 14.6 s, 356,904 B, 6.29 GB;
  - $k = 32$: 6,751,799 cycles, 14.2 s;
  - the out-of-bound noise witness does not prove.
- **`FheRequest.yul`** accepts one input per transaction on its leanSTARK triple. On the test
  network, modelled, the request was mined (block 702,460) with `VERIFY` at 7,940 gas, hashing the
  ciphertext included. The changed ciphertext and the next request number were both refused.
- **Results and the local chain's procedure** are in experiment 41's README (`eb76c78`). Code:
  kohaku-rs `experiment/q8-fhe-input` `a9ca8d3`.

### Learned

- At tfhe-rs's parameters a leanVM proof of the ciphertext's well-formedness fits, but only after
  leaving the base field: integers as exponents of a primitive element of $\mathrm{GF}(2^{192})$,
  where $g$'s order $2^{64} - 1$ is too small to hold a sum.
- leanVM bounds a proof's committed witness at $2^{28}$ words. A program's cycle count is what
  decides whether a statement can be proved at all.
- The program's key must be the hash of the instantiated source, since the chain's verifier
  compiles the file as it stands.
